# 遇到问题时，先让自己的 Agent 帮忙

直接描述你刚做了什么、看到了什么。例如“页面打不开，帮我检查这个 FrontierDock 工作区”，或者“这篇摘要一直没补齐，请核对来源”。不必先学会命令，也不必一出错就去 GitHub 提交反馈。

Agent 可以先运行 `doctor` 和 `plan`，再查看本地维护报告。原始报告可能含研究资料，留在本机分析即可。

| 现象 | Agent 应先检查的地方 |
|---|---|
| 页面打不开 | 服务是否运行、Python 版本、端口是否被占用。需要时选择另一个空闲端口，别停掉别人的服务 |
| “不是工作区” | 是否选中了初始化过的独立目录。不要在非空目录强行初始化 |
| 没有期刊或论文 | 空白工作区本来没有资料；先配置核实过的期刊，再执行检索和导入 |
| 摘要仍然缺失 | 原站是否提供 Abstract、是否核对了题名和 DOI、是否真正执行了 Agent 队列 |
| 有原文但译文为空 | 翻译模式、原摘要指纹、调用上限、账号访问和模型输出是否完整 |
| 有“身份冲突” | 用 `conflicts` 查看本地差异，核对 DOI 官方页面，保留原记录。核对后记录证据，不自动合并 |
| 某刊整年没有补齐 | 当前 Crossref 检索只取有限窗口；请 Agent 对照官方目录分页补录。库存空档不等于出版空档 |
| 免费模型不能调用 | 免费额度是否过期或用完、库存是否超过 24 小时、服务商是否支持该模型。不能据此自动改成付费 |
| 有定时时间却没有自动运行 | 配置只是计划；检查外部定时器和实际 Agent runner 是否安装并运行，电脑是否开机 |
| 工作区忙 | 先确认上一次维护进程是否还在。只有确认它已退出，才由 Agent 处理遗留锁 |
| 阅读状态写入冲突 | 刷新后按最新状态重试；不要覆盖另一个窗口的新修改 |
| MinerU 失败 | 用户是否选过本地/云端模式，本地程序或云端权限是否可用；云端上传是否获准 |

常见配置、端口和依赖问题，Agent 可以在授权范围内直接修复，并再次打开页面验证。遇到网站限制、没有公开摘要或账户权限不足，应说明具体缺口，不能编写内容填空。

如果还有稳定复现的程序缺陷，再请 Agent 用虚构记录制作最小复现。只整理程序版本、系统大版本、复现步骤和脱敏错误码，交给你看过后再提交。不要上传整个工作区、原论文、API 密钥或原始账户日志。
